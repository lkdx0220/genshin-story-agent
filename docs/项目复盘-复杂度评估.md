# 项目复盘：我为什么低估了这个项目的复杂度

> 撰写时间：2026-09-07
> 背景：这是作者亲手搭建的第一个 AI 项目。最初的想法是——“一个 LangGraph 架构 + RAG，知识库用 wiki 上现成的数据，再参考一份框架，大概一星期就够了。”

## 一、原假设为什么看起来成立

最初的想法在纸面上是完全合理的：

```text
LangGraph：官方文档 + 示例很多
RAG：BM25 / 向量库 / RRF 都是成熟技术
知识库：wiki 上有现成的原神剧情数据
框架：有参考实现可以照着搭
```

如果目标是“跑通一个能在命令行回答两句剧情问题的 demo”，一星期确实够。问题在于，真正的目标不是 demo，而是：

- 能稳定回答 25 类 Golden Test 问题；
- 能扛住长任务、极端长文档；
- 能分发给别人使用；
- 能持续迭代而不退化。

这是两个完全不同的工程。

## 二、三个被严重低估的约束

### 1. 数据约束：wiki 数据不是“现成的”

“知识库是 wiki 上现成就有”是最大的误判。实际遇到的：

- 观测枢是 SPA，网页直接抓不到正文；
- 部分 wiki 站点返回 403；
- 真正可用的 `entry_page` 接口需要逆向 JS bundle 才能找到；
- 抓到后还有双层 JSON、HTML、任务系列关系混乱、同名任务、脏数据；
- 任务名、角色名、书籍名、专名必须精确对齐，否则 Golden Test 直接失败。

WorkBuddy 那一次对比最能说明问题：它用了 4 个任务词条 + 22 张地图文本 + 3 件圣遗物 + 组织/区域/讯息条目，并且这些条目是顺着 `data-entry-id` 链接一张一张扩出来的。也就是说，**“拿数据”本身就是一整条信息获取管线**，不是下载一个 JSON 文件。

### 2. 模型约束：Agent 不是“搭好图就会跑”

LangGraph 的图半天能画完，但模型行为是非确定性的。这个项目实际修过的模型问题：

- 计划写了工具名，但不发结构化 tool_calls（R7）；
- 凭空搜不相关的任务（X7 搜了丝柯克）；
- 把“磨损”这类比喻词加进检索 query，反而污染检索（C1）；
- 拿到全文后提前收工，漏掉关键维度（R2）；
- 把成功工具结果误判成 not_found，直接“当前知识库未收录”；
- 熔断逻辑在“部分工具失败但已有大量成功结果”时误杀长任务。

结论：**在 RAG Agent 里，代码一半是在跟模型的非确定性搏斗。** 提示词是约束，但只有代码级硬规则才可靠。

### 3. 可靠性约束：能回答一次 ≠ 能一直回答

从“跑通一次”到“可以交付”，中间多出来的东西：

- Golden Test 25 题 + 确定性评估器；
- 别名消歧、意图路由、工具分组；
- 熔断、限流、SSRF 白名单、安全扫描；
- 流式输出、前端状态、桌面打包；
- 远程版、令牌鉴权、客户端本地历史；
- 向量索引、rerank、检索质量过滤；
- 知识库更新流程与回归验证。

这些每一项单看都不大，合起来就是“最后 20% 吃掉 80% 时间”的典型样本。

## 三、现在看当初的想法

**不是天真可笑，而是典型的“demo 思维”。**

- 把“能跑”当成了“完成”；
- 把“技术名词”当成了“工作量”；
- 把“wiki 有数据”当成了“数据可用”；
- 把“模型会思考”当成了“模型会稳定执行”。

这几乎是每个第一次做 AI 项目的人都会踩的坑，而且这个误判是必要的：如果一开始就完全知道有这么多坑，大概率不敢动手；正因为低估了，才真的把项目做起来了。

## 四、修正后的工期公式

以后再估类似项目：

```text
预计工期 = 数据可用性调查 + 核心技术打通（真正的 30%）
         + 数据清洗与索引（×1.5~2）
         + 模型行为约束与兜底（×1.5~2）
         + 评测体系与回归（×1~1.5）
         + 交付形态（打包/远程/安全）（×0.5~1）
```

经验值：

```text
demo 工期 ≈ 1 周
可评测、可稳定交付的系统 ≈ demo 工期 × 3~5
领域数据需要逆向/清洗时，再 × 2
```

## 五、这段经历真正沉淀下来的东西

比代码更值钱的是这几条判断能力：

1. 数据决定了 RAG 的上限，检索策略决定能不能摸到上限；
2. 评测体系是所有改动的裁判，没有它一切优化都会变成玄学；
3. 提示词负责方向，代码负责兜底，不要只靠提示词；
4. Agent 的每个“智能动作”都需要一个“不智能的守卫”；
5. 交付给别人的系统和自用脚本，工作量差一个数量级；
6. 会从 trace 反推模型行为，比会写 Prompt 更重要。
